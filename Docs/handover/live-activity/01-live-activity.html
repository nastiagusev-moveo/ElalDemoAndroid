Flight Live Updates on Android

How the elal-flight-sdk turns server push messages into an Android 16 "Live Update" notification. It covers the journey stages, how changes move from the demo app into the production app, and how to fire test pushes from Postman.

NNCrafted with care by Netanel Boris Niazov · October 2026
Android 16+ (API 36). Older devices silently no-op Notification ID 7001 Channel elal_journey 11 journey stages Transport: FCM data messages
Table of contents

What's in this handover

1 · Server

Sends an FCM data push

Every field is a string. event = start / update / end, plus the current stage.

2 · Host app

Parses it into FlightContentState

Demo: FlightMessagingService. Prod: FcmService + LiveUpdatePushParser. Missing fields are carried forward from the last state.

3 · SDK

LiveUpdateManager renders

Builds a ProgressStyle notification, persists the state, runs a 23h watchdog, and during DEPARTED ticks the plane forward by itself.

Workflow

Develop in the demo, ship to production

All SDK work happens in the demo app first, because it builds fast and has a debug UI. When a change is verified, the SDK module is copied into the production repo. The host-app glue code is different in each repo, so it is never copied. You port it by hand.

Sync procedure

Check what differs before copying

Both copies were identical when this doc was written (8 Oct 2026), so any difference you see is new work.

diff -rq -x build -x .gradle ~/ElAlDemoAndroid/elal-flight-sdk ~/Android/elal-flight-sdk
Copy the SDK module across

If step 1 listed a file that exists only in ~/Android, find out why before overwriting anything.

rsync -av --exclude build --exclude .gradle ~/ElAlDemoAndroid/elal-flight-sdk/ ~/Android/elal-flight-sdk/
Port host-side parsing changes by hand only if the payload changed

If you added a new field to FlightContentState, you must also parse it in LiveUpdatePushParser.kt. The two parsers are written differently (prod requires activityId and event, and parses enum values case-sensitively), so this can't be a copy-paste.

Re-test against the production app

Switch the payload builder to Production. This needs a service-account key from the elal-4d92d Firebase project, because the demo key cannot push to the prod app.

Hands-on

Sending a test push with Postman

You need two secrets: a short-lived OAuth access token, which proves you may send, and the phone's FCM registration token, which says where to send. Tick each step as you go. Your progress is saved in this browser.

P

Fast lane: import the ready-made Postman collection

ELAL.postman_collection.json sits in the same folder as this page. It has one request per stage plus END.
⬇ Download collection
  1. Postman → Import → choose ELAL.postman_collection.json.
  2. Open the collection → Variables tab and fill in the three values below. Every request inherits them, so there is nothing to edit per request.
    accessToken
    The ya29… token from step 3. Refresh it about every 60 minutes.
    deviceToken
    The phone's FCM token from Logcat.
    projectId
    elaldemoandroid (demo) or elal-4d92d (prod).
  3. Send CHECK_IN first (it is the start event), then the other stages in order. Send END to dismiss the notification and reset.
POSTCHECK_INPOSTGATE_READYPOSTAwaiting_Boarding_1.4POSTBOARDINGPOSTLAST_CALLPOSTDEPARTURE_PENDINGPOSTDEPARTEDPOSTLanding_soon_1.4POSTLANDEDPOSTBAGGAGEPOSTEND
Each request is a snapshot from a past test.The dates are in the past and the flights and activityIds differ between requests. For DEPARTED, set departureTime close to now, or the countdown jumps straight to "Landing soon". Sending to production? Add a flightNumber to CHECK_IN first, because the prod parser drops a start without one. Use the payload builder for fresh, consistent payloads.

When it doesn't work

        
Troubleshooting

      

      
      

        
401 UNAUTHENTICATED Access token expired
The ya29… token lives for at most 1 hour. Run step 3 again and paste the new token into Postman's Authorization tab.

        
403 SENDER_ID_MISMATCH / PERMISSION_DENIED Wrong Firebase project
The service-account JSON, the project in the URL, and the app on the phone must all belong to the same Firebase project: demo → elaldemoandroid, prod → elal-4d92d.

        
404 UNREGISTERED / NOT_FOUND Stale device token
The app was reinstalled or its data was cleared. Get a fresh token from Logcat.

        
400 INVALID_ARGUMENT Malformed body
The usual causes are: (1) a non-string value in data, for example "flightDuration": 210 where FCM requires "210"; (2) smart quotes (” “) from copy-pasting; (3) a trailing comma.

        
200 OK, nothing shows FCM accepted it but no notification

          
    
            
  • The device is below Android 16 (API 36). Every SDK entry point silently returns success.
    • 
            
  • The notification permission or POST_PROMOTED_NOTIFICATIONS was denied. startJourney returns NotificationsNotEnabled.
    • 
            
  • Prod: the payload has no activityId, or event isn't exactly start|update|end. It is then treated as a legacy marketing push, not a Live Update.
    • 
            
  • Prod: a lowercase value such as "stage": "boarding". The prod parser calls Stage.valueOf() without uppercasing, so the parse fails and the push is dropped. Look for LiveUpdatePushParser-> parse-> failed in Logcat.
    • 
            
  • Demo: start sent while a journey is already active. It returns ActivityAlreadyRunning. Send end first (prod ends the old journey automatically).
    • 
            
  • Prod: update sent with no active journey. It returns NoActiveActivity. (Demo promotes it to a start.)
    • 
          

        
DEPARTED countdown wrong Plane or countdown time is off
The arrival is computed as departureTime + departureTimezoneOffset + flightDuration, and "now" comes from FCM's sent_time, not the phone clock. Send both departureTimezoneOffset (e.g. "+03") and flightDuration in minutes. Look for the 📋 JOURNEY TIMELINE block under tag LiveUpdateManager. It prints every input and the interval it settled on. A missing offset logs departureTimezoneOffset missing/unparseable.

        
Notification vanished Journey ended by itself
One of three things happened: a COMPLETED stage arrived (it ends the journey just like event=end); the 23-hour watchdog fired after no server event in that time; or an end event was sent.

        
Carousel disappeared Baggage belt cleared on next update (demo)
On purpose, the demo parser does not carry baggageCarousel forward. A missing or blank value clears it, so resend it with every LANDED/BAGGAGE update.

        
startForegroundService denied Log line during DEPARTED
The app was in the background, so Android 12+ blocked the in-flight keep-alive service. This is expected and handled: the notification still updates. Sending with android.priority: HIGH gives the app an exemption window.
